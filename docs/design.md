# 技术设计

DFX Agent 将任务描述、项目源码和可选日志交给模型，通过工具观察逐步完成调查、修改和检查。网页与 CLI 共用执行入口，前端展示实际记录，不自行补充模型答案。

```text
任务 + 项目 + 资料范围 + 可选工具链配置
  → 独立工作副本
  → Agent 循环 ↔ 模型 ↔ 文件 / 命令 / HarmonyOS 工具
  → 自主检查与反馈修订
  → 最终声明、补丁、用量与执行记录
```

| 模块 | 职责 |
|---|---|
| workbench / CLI | 输入配置、启动、观察、停止、显式继续及导出 |
| agent / model | 原生工具调用、完整历史、请求计数与最终声明 |
| task / tools | 项目副本、资料范围、文件搜索与编辑、命令执行 |
| harmony_tools / harmony_device | 构建、部署、页面布局、输入、导航及故障日志 |
| harmony_script | 让模型自行编写检查脚本，调用相同共享设备接口 |
| continuation / run_report | 明确等待后的恢复、累计记录和结果汇总 |

模型可根据错误或断言失败修改方案。只读调用可以顺序执行，多动作并不隐含并行执行。工具结果通过对应调用 ID 返回；工具参数不完整或无效时不执行。

上下文保留完整历史，使用本地 tokenizer 估计容量，实际 token 消耗来自服务商 usage。没有传输自动重试或自动有损摘要。请求额度内可保留最后一次声明轮，用于如实提交已有结果，不强制声明成功。

通用 [HarmonyOS Skill](../src/dfx_agent/skills/harmony-debug/SKILL.md) 描述工具用法和诊断方法，不指定某题的根因或修复步骤。部署与依赖准备需要对应权限；窗口不可见等状态回传给模型判断，真实技术故障保留记录并停止。

源码中的范围检查用于约束任务操作，不是操作系统安全沙箱。执行不可信项目应使用隔离的工作环境。
