# 输入输出 Spec

## 输入

- 必需：项目目录、自然语言任务、结果目录。
- 真实模型：本机 API 环境变量，以及已确认可外发的范围 JSON。
- 可选：经过审阅的故障日志目录、只读文件规则、HarmonyOS 主机配置。
- 任务描述写明故障和预期行为；未明确的关键业务语义由操作者决定，不编造验收答案。

## 执行

1. 创建独立工作副本，排除密钥及配置指定的私有资料。
2. 模型自主搜索、读取、编辑和执行检查；调用结果保留原始状态。
3. 需要操作者决定协议或处理环境时显式等待；处理完后可在完整边界继续同一任务。
4. 最终通过 `finish` 声明修改、定位、实测和未验证内容。没有执行的检查不能写成通过。

## 输出

| 文件 | 内容 |
|---|---|
| task.json / launch.json | 输入与配置 |
| model/ | 请求、返回与错误记录 |
| trajectory.json | 完整模型及工具历史 |
| tools/events.jsonl | 工具动作与回执 |
| patch.diff | 候选差异 |
| result.json / report.md | 终态、声明、资源与限制 |

`Submitted` 代表模型提交了声明；失败、额度耗尽或环境阻塞也保留记录。业务结果依据实际输入输出、断言和行为判断。可额外使用独立检查，但不把独立答案放进模型上下文。
